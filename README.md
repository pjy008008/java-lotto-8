# java-lotto-precourse

## 프로젝트 소개
이 프로젝트는 주어진 요구사항에 따라 로또 게임을 구현하는 프리코스 3주차 과제입니다.
사용자가 로또 구입 금액을 입력하면, 애플리케이션이 티켓을 발급하고, 사용자가 당첨 번호와 보너스 번호를 입력하면, 애플리케이션이 당첨 통계 및 전체 수익률을 표시하는 콘솔 애플리케이션입니다.

## 주요 기능
* **로또 티켓 구매:** 사용자가 로또 티켓을 구매할 금액을 입력.
* **로또 티켓 발급:** 구매한 금액을 기준으로 로또 티켓을 자동으로 발급. 각 티켓은 1부터 45 사이의 6개 고유 숫자로 구성됨.
* **당첨 번호 입력:** 사용자가 추첨의 당첨 번호 6개와 보너스 번호 1개를 입력.
* **당첨 확인:** 발급된 로또 티켓을 당첨 번호 및 보너스 번호와 비교하여 당첨 순위를 결정.
* **결과 출력:** 당첨 통계(순위별 개수)를 출력, 구매 금액 대비 총 수익률을 계산 후 출력.
* **예외 처리:** 유효하지 않은 사용자 입력에 대해 `IllegalArgumentException`을 발생, `[ERROR]`로 시작하는 에러 메세지를 출력 후 해당 단계부터 다시 입력 수행.

## 기능 요구사항 체크리스트
**로또 구매**
* [ ] 사용자로부터 1,000원 단위의 구매 금액을 입력받음 (예: `3000`, `10000`).
* [ ] 금액에 따라 발급할 티켓 수를 결정 (예: 3,000원일 경우 3장).

**로또 티켓 발급**
* [ ] 결정된 수만큼 로또 티켓을 자동으로 발급.
* [ ] 각 로또 티켓은 1에서 45 사이의 6개 고유 숫자를 포함해야 함 (티켓 내 중복 없음).
* [ ] 발급된 로또 수량 및 번호를 출력, 번호는 오름차순으로 출력.
  ```
  3개를 구매했습니다.
  [8, 21, 23, 41, 42, 43] 
  [3, 5, 11, 16, 32, 38] 
  [7, 11, 16, 35, 36, 44]
  ```

**당첨 번호 입력**
* [ ] 사용자로부터 6개의 당첨 번호를 쉼표(,)로 구분하여 입력 받음. 각 번호는 1에서 45 사이여야 함 (예: `1,2,3,4,5,6`).

**보너스 번호 입력**
* [ ] 사용자로부터 1개의 보너스 번호를 1에서 45 사이의 숫자로 입력 받음. 당첨 번호와 구별되야 함.

**결과 발표**
* [ ] 구매한 각 로또 티켓을 당첨 번호 및 보너스 번호와 비교하여 결과를 결정.
* [ ] 다음 기준에 따라 각 당첨 순위의 개수를 계산.
  * 3개 일치 (5,000원)
  * 4개 일치 (50,000원)
  * 5개 일치 (1,500,000원)
  * 5개 일치 + 보너스 번호 일치 (30,000,000원)
  * 6개 일치 (2,000,000,000원)
* [ ] 당첨 통계를 지정된 형식으로 출력.
  ```
  당첨 통계
  ---
  3개 일치 (5,000원) - n개
  4개 일치 (50,000원) - n개
  5개 일치 (1,500,000원) - n개
  5개 일치, 보너스 볼 일치 (30,000,000원) - n개
  6개 일치 (2,000,000,000원) - n개
  ```
* [ ] 총 수익률을 계산 (총 당첨금 / 구매 금액 * 100).
* [ ] 총 수익률을 소수점 둘째 자리에서 반올림하여 출력 (예: `총 수익률은 62.5%입니다`).

**예외 처리**

다음 경우에 대해 `IllegalArgumentException`을 발생, `[ERROR]`로 시작하는 에러 문구를 출력 후 현재 단계부터 사용자 입력을 다시 받음

* **구매 금액 입력 시:**
  * [ ] 입력값이 유효한 숫자가 아닌 경우.
  * [ ] 입력 금액이 1,000으로 나누어 떨어지지 않는 경우.

* **당첨 번호 입력 시:**
  * [ ] 입력이 쉼표로 구분되지 않았거나 (쉼표 외) 숫자가 아닌 문자가 포함된 경우.
  * [ ] 숫자 개수가 정확히 6개가 아닌 경우.
  * [ ] 숫자가 1에서 45 사이의 범위를 벗어난 경우.
  * [ ] 6개의 당첨 번호 중 중복된 숫자가 있는 경우.

* **보너스 번호 입력 시:**
  * [ ] 숫자가 1에서 45 사이의 범위를 벗어난 경우.
  * [ ] 보너스 번호가 이전에 입력한 6개의 당첨 번호에 이미 포함되어 있는 경우.

### 개발 시 지켜야 할 것들
본 프로젝트 개발 시 특히 유의해야 할 주요 가이드라인을 정리한 내용

* **들여쓰기(Indent) 깊이 제한:**
  * 함수(메서드) 내에서 코드 들여쓰기는 최대 2단계까지만 허용.
  * 들여쓰기 깊이를 줄이기 위해 함수(메서드)를 적극적으로 분리.

* **함수/메서드 최소화:**
  * 함수(메서드)의 길이가 15라인을 넘어가지 않도록 구현.
  * 함수(메서드)는 한 가지 책임만 갖도록 최대한 작게 구현.

* **Java Enum 사용:**
  * Java Enum을 적용하여 프로그램 작성.

* **Lotto 클래스 관련:**
  * 제공된 `Lotto` 클래스 사용.
  * `numbers`이외의 필드(인스턴스 변수) 추가 불가.
  * `numbers`의 접근 제어자(`private`) 변경 불가.
  * `Lotto`의 패키지 변경 가능.

* **하드코딩 최소화:**
  * 코드 내 문자열, 숫자 값을 상수(`static final`)로 정의.
  * 상수 값이 어떤 역할을 하는지 명확히 표현.

* **변수 이름에 자료형 사용 제한:**
  * 변수 이름에 자료형이 사용되지 않도록 구현.
  * 자료형은 코드 작성 시점에 자연스럽게 이해될 수 있도록 함.

* **테스트 코드 작성:**
  * 구현된 기능 목록이 정상적으로 작동하는지 JUnit 5와 AssertJ를 사용하여 테스트 코드를 작성하고 검증.
  * 테스트는 작은 단위부터 시작해 큰 단위의 테스트 순서대로 테스트.
  * 구현한 기능에 대한 단위 테스트 작성. 단 UI(`System.out`, `System.in`, `Scanner`) 로직은 제외.
